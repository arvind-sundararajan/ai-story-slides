Introduction

TrueFoundry built Cognita for document retrieval.

Cognita is an open-source project developed by TrueFoundry, first released with a set of features to support multiple document retrievers and incremental indexing. The specific problem it was built to solve is the efficient retrieval of documents based on similarity search, query decomposition, and document reranking. This is achieved through the use of various components such as the API server, data indexing, and the LLM gateway, which work together to provide a production-ready environment for document retrieval.

The architecture of Cognita is technically different from alternatives due to its use of a vector database, indexing job, and model gateway. These components enable Cognita to support state-of-the-art open-source embeddings and reranking, as well as the use of large language models. The project also utilizes a metadata store to keep track of already indexed documents and prevent re-indexing, reducing the compute burden. Additionally, Cognita supports incremental indexing, which allows for the ingestion of entire documents in batches.

Cognita is designed to be used in various environments, including local setups and production-ready environments. It offers no-code UI support, making it accessible to a wide range of users. The project also supports multiple use cases, such as RAG customizations, audio and video parsing, and multi-modal vision parsing using GPT-4. The use of Docker and docker-compose for installation and deployment makes it easy to set up and manage Cognita in different environments.

The target audience for Cognita includes developers and users who need to efficiently retrieve documents based on various criteria. The project's support for multiple document retrievers, incremental indexing, and state-of-the-art embeddings and reranking makes it a useful tool for a wide range of applications. However, it is worth noting that the project is no longer actively maintained, which may impact its future development and support. Despite this, Cognita remains a valuable resource for those looking to build efficient document retrieval systems.

Enhance reranking with Ollama and Infinity Server

To integrate Ollama and Infinity Server for enhanced reranking, we need to understand the architecture of Cognita Components, which includes Data Indexing, Question-Answering using API Server, and Code Structure. The research highlights the use of docker-compose for local setup and production-ready environment. We can use the docker-compose --env-file compose. env up command to start the services.

The modelsconfig. yaml file is used to configure the models, and the embedderconfig is used to configure the embedder. The provider config key is used to specify the provider for the embedder.

The Cognita Components include Data Indexing, which is responsible for indexing the data, and Question-Answering using API Server, which is responsible for answering questions based on the indexed data. The Code Structure includes the use of payload. py for payload management. The research also mentions the use of getdevicename() function to get the device name, which can be mps, cuda, npu, hpu, or cpu.

The research highlights the use of ainvoke, agetrelevantdocuments, aretrievedocuments, and agetrelevantdocuments methods for answering questions. The ainvoke method is used to invoke the agent, while the agetrelevantdocuments method is used to get the relevant documents. The aretrievedocuments method is used to retrieve the documents, and the agetrelevantdocuments method is used to get the relevant documents.

The use of docker-compose --env-file compose. env --profile ollama --profile infinity up command is highlighted in the research for integrating Ollama and Infinity Server. The --profile ollama and --profile infinity flags are used to specify the profiles for Ollama and Infinity Server respectively. The research also mentions the use of pydantic v2 for payload management.

The research mentions the limitation that the aunassociatedatasourcewithcollection function in prismastore. py removes only the data source from the collection but does not remove the associated data points ingested in the vector DB. This limitation can cause issues with data consistency.

The use of multi-modal vision parser using GPT-4 is highlighted in the research for parsing multi-modal data. The research also mentions the use of AudioParser and VideoParser for parsing audio and video data respectively. The Metadatastore is used to store the metadata for the data.

The research highlights the use of incremental indexing for indexing the data incrementally. The RAG component is used for reranking the answers. The RAG component uses the Similarity Search, Query Decompostion, and Document Reranking methods for reranking the answers.

The callout is that the operation 'signoutmps()' does not support input type 'int64' in MPS backend which is a limitation of the MPS backend.
